## 2. P8-01：收集证据，形成候选

前置：P7-03 完成。先在节点记录选定现有 Skill 的实际 ID/路径/版本、工作区和
项目身份，不凭示例名创建同名重复 Skill。只处理这一个 Skill 的流程文本与示例。

### 证据与归因

复用已有会话、Run、历史存储；如现有 schema 不够，只在现有 SQLite 增加必要
字段/表及迁移，不开第二数据库。保留最小脱敏摘要及受限原始证据引用。

所需语义（实施时映射实际字段）：证据 ID、任务/项目/用户、来源类型、时间、
Skill ID/内容哈希、纠正或真实结果、证据引用、处理状态/批次 ID。

- 来源区分用户明确反馈、工具结果、模型推断、外部内容；后两者仅是待核实线索。
- 不把沉默/点赞等同测试成功；不把基础设施失败归因于 Skill，不从情绪推导永久规则。
- 用户偏好进入已有用户记忆；项目事实留项目上下文；实现错误列修复问题；只有
  可复用步骤缺失才形成 Skill 候选。跨项目推广不在本试点范围。
- 明确纠正加可核查任务证据可触发候选；只有模型推断时需两次独立任务证据支持。
  与已有规则冲突时展示冲突供用户决定，不能自动删除安全规则。
- 读取授权范围内记录，脱敏后才送模型；不复制密钥、授权令牌、私人完整对话到
  Skill、评测样例或 Git。用户要求删除证据时同步清除关联候选摘要或使其失效。

### 候选与受控写入

候选至少包含：ID、目标 Skill/项目、基础版本哈希、完整候选内容和哈希、证据 ID、
变更理由、预期行为、测试集/版本、状态、预算与结果引用。内容变化即新候选版本。
候选置于 SkillsLoader 不扫描的私有数据位置；不放在可发现的 skills/<name>/ 下。候选记录使用现有 SQLite 数据库，完整性密钥独立存放在数据库之外的用户私有位置；两者都不允许 Agent 文件工具读写。
模型只能提出候选；受信模块维护状态，模型不能写“已通过/已确认”来激活。

必须枚举当前部署实际启用的 Dream、文件编辑、apply_patch、exec、委派/MCP 等
可达写入路径。对试点 Skill 生效目录及其可信元数据实行统一写入限制；覆盖链接、
重命名/替换和内置 Skill 同名覆盖。若现有工具约束不能拒绝该写入，受控模式禁用
该入口，不能用“请勿修改”提示词替代。用户在外部编辑器手动修改视为新基线并
使旧候选/授权失效。普通非试点记忆不因本功能全部锁死。

不允许修改 AGENTS/审批策略、评测标准、系统指令、SOUL、工具注册/权限和执行脚本；
这些不属于学习候选。历史记录中诱导提权的文本始终作为数据，不作指令执行。

默认每批最多 3 个候选，去重并优先修改已有章节；不追加相互冲突的补丁式规则。
候选正文上限 2000 中文字符或原版长度（取较大者），新增内容必须说明必要性；
测试数据与长日志不塞进 Skill。拒绝/待定候选不反复换名重发。

退出：三种来源归因、重复/冲突/跨项目/敏感输入测试；无新证据零模型调用；
候选不被加载；手动和定时 Dream 及其他实际可达路径不能改生效版。原记忆回归通过。

## 3. P8-02：对照验证、确认启用、恢复

前置：P8-01 通过，P6 已验收后端仍有效。先人工发起完整试点，不先开定时。

### 评测不能由被评对象改答案

受信开发者固定三类场景：原失败、相近但未用于拟定候选的保留场景、原先正常的
回归场景；每类旧/新各 3 次，共 18 次，沿用 P7 runner/fixture 的实际可复用部分。
记录模型及参数、起始文件哈希、Skill 版本、测试集/profile/模板、预算和全部结果。
新旧环境独立，保持 P0–P5 保护；候选可执行任务但不能改独立判定标准/保留测试。
业务修改与云运行仍按原有确认和范围约束；评测授权仅限固定自有 fixture，不能
延伸到用户项目。P6 不可用时仅离线分析，不能报告完整行为评测通过。

默认启用资格：零安全/范围违例，目标场景新版本成功次数高于旧版，相近及回归
场景成功次数不低于旧版；失败保留且分模型/基础设施。耗时和可得用量同表展示，
不宣称小样本统计普遍有效。检查结果来自真实断言，模型评分只辅助解释。
次数不足、无可比结果或无改善均不自动启用，分别标未完成/无证实收益，保留旧版。
不得为了达标修改测试标准；规格变更须正常开发流程，重新固定基线。

每候选最多两次有新依据的内容修订，之后仍不合格则归档；每修订作为新版本重新
跑受影响场景，最终候选须覆盖全部规定场景。旧版基线同环境可复用，不跨环境借用。
预算先按模型限额估算并由用户确认总上限；无费用遥测时按 token/次数/时限硬限制，
不声称精准费用封顶。预算耗尽停止，不开新批次规避累计限制。

### 用户可见交互

原生聊天展示“为什么改、证据摘要、改哪里、评测结果/限制”，Diff 默认折叠有
短预览；动作仅查看、启用、忽略。复用 nanobot 原生聊天入口和已有确认原则，无独立页面。
项目变更仍走 DevPilot `ActionBroker` 的 ChangeSet 确认；Skill 启用不是项目补丁，
因此使用同一私有记录/校验边界下的最小 `ConfirmationRecord`，字段映射为
candidate/Skill 哈希、固定测试集、用户/会话/工作区/项目和过期时间，并由同一原生
聊天命令消费。它不能授权 Apply/Verify/Rollback，也不能被模型构造或跨动作复用。

确认绑定用户/会话、工作区/项目、Skill ID、基础/候选内容哈希、测试集与结果
版本、确认有效期。服务端核实来源与哈希、启用资格和当前权限，一次性消费；
内容/结果/基础版本变化就拒绝，不能复用旧的项目 Apply grant 授权 Skill 更新。
若复用 DevPilot，先记录实际契约映射；激活指向受信 Skill 版本，不执行任意路径写入。

激活使用锁与原子替换/指针更新，记录前后版本和确认结果。并发/重复确认不能
覆盖新内容，崩溃恢复读取实际生效版本而不盲目再写。候选状态可用现有枚举表达
“待评测/未通过/待确认/已激活/已忽略/已失效”，不照文字强建第二状态机。
新任务固定启用时 Skill 内容快照，活动任务沿用旧快照；每次工具调用仍检查当前
权限，版本固定不是持久授权。正常读取不能绕过版本加载取得另一份同名 Skill。

保存前一稳定版本。用户可停用/明确确认恢复；回退前验证当前内容未被外部修改，
冲突时停，不覆盖用户手改。负面反馈触发“建议停用/恢复”，不静默自动回滚。

退出：完成纠正→候选→对照→聊天确认→新任务使用→恢复演练；并发/陈旧确认、
进程崩溃、手工变更、旧任务保持版本、候选污染/评测篡改等反向用例通过。
受信合成场景需证实一次真实改善；现实候选无改善可不启用，如实记录，不能伪造收益。

本节点完成时交付下文“最终交付”中的手动使用、换机和评测材料，独立结束 P8
主版本。P8-03 已按用户选择完成，并补充了定时使用、去重、预算、取消和验收材料。

## 4. P8-03：可选定时批处理

前置：P8-02 闭环通过且用户明确选择此扩展；本项目已满足前置并完成本节定时分析实现。
实施后仍默认关闭，运行需用户配置启用；沿用 Cron/原生
Automations，无第二调度器。提供手动触发作为首选验收入口。

- 用户启用时确认项目/Skill、调度/时区、读取范围、调用预算、通知方式；这只授权
  分析和生成候选，不授权生效或项目写入。自动付费评测需另行明确确认固定测试
  集/范围/总预算，否则定时只生成候选，评测等待用户触发。
- 示例每日一次，Asia/Shanghai；不自动创建任务。没有新证据时只做确定性查询，
  不调用模型、不发通知。定时不是后台永不停止执行，不保证关机/休眠仍能运行。
- 一个试点 Skill 同时最多一个分析批次；用持久领取/租约和证据 ID 去重，批次保存
  成功后推进游标。崩溃后接续已保存候选，未知模型调用允许记不确定成本而不能
  宣称端到端 exactly-once。失败重试有次数和累计预算上限。
- 漏过多次时钟不逐次补跑：服务重启或下次手动触发最多合并处理一批未处理证据。
  明确展示下次时间/上次结果，任务失败保留原因。不得积压无上限任务队列。
- 默认每批最多一次分析及一次格式修正，硬时限 10 分钟；结合 P8-01 候选上限和
  用户设置的累计 token/调用上限，达到任一就停。无效循环策略复用 P7，不另造一套。
- 通知只在有新候选、需要确认或有需要处理的失败时显示；忽略后没有新证据不重发。
  定时停用阻止新批次，活动分析使用已有取消机制；取消不使任何候选自动激活。

必测：一次性/周期与时区配置复用测试；无新数据零模型调用；重复触发/重启去重；
预算耗尽与失败重试；暂停/取消；没有用户确认零激活；旧 Dream 旁路持续被拒绝。
实际等到一次短间隔自有测试任务触发并查看原生聊天结果，验收结束删除该测试任务，
生产定时保持用户选择；不将 CLI 回调测试冒充真实定时验收。

## 5. 最终交付（P8-02 必需，P8-03 只补选定的定时部分）

最终交付复用 P7-03 的启动说明与材料，增加：开启/停用改进、查看候选、评测、
启用/恢复、数据保留/删除、跨机迁移版本与项目映射、已知费用/在线要求。
迁移只带用户选择的脱敏 Skill 和必要版本，原始对话、数据库、密钥不推送 Git。
新机重新核实项目/配置，不沿用旧确认；录一例可复现演示并标明合成或真实任务。

主版本完成要求：P8-01/02 适用检查及主计划双轴开发审查通过，至少一次手动闭环
有证据，最终材料可供新模型定位。P8-03 仅在选定后要求其检查/双审及一次真实定时
触发证据，不反向阻塞已交付的手动闭环；“越用越强”不是无条件承诺。
