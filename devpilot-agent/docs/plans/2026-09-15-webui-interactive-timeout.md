# WebUI 交互请求超时收口

日期：2026-09-15；状态：已实施并验证。

## 背景

原生 nanobot WebUI 的 `Running` 仅在收到后端 `turn_end` 或 `goal_status=idle`
时结束。真实自然语言代码分析请求可在模型流式调用无后续事件时长期占用同一会话锁；
页面因此持续计时，后续消息只能停在“发送中”。这不是前端把进度文本误判为完成，
而是交互请求的后端终态到达过慢。

## 已确认设计

1. 保持后端终态为唯一事实来源：前端不得本地伪造成功或释放一个仍可能写入的任务。
2. 为 WebUI 的模型请求使用独立、有限的交互超时；超时要被转换为可展示的失败回答，
   并沿用现有 delivery 的 `turn_end` 与 `idle` 收口，从而释放同一会话锁。
3. 保留全局和持续目标的长任务语义；不改变 FC 工具执行时间，也不改变 Apply、Verify、
   Rollback 的确认契约。只约束等待模型响应的 WebUI 交互请求。
4. 前端继续只依据 `turn_end` / `idle` 停止计时；补回归用例证明超时终态会清除
   `runStartedAt` 与 `isStreaming`，并展示失败回答而非无限 `Running`。

实现参数：`NANOBOT_WEBUI_LLM_TIMEOUT_S` 默认 `75` 秒；设为 `0` 可由本机运维显式
关闭。非法、`NaN` 或无穷值回退默认值。仅普通 WebUI 回合使用该上限，Cron 与持续目标
不受影响。

## 验收

- 用受控的永不返回 Provider 测试 WebUI 请求在交互超时后产生失败回答、`turn_end` 和 `idle`。
- 同一会话随后能接受另一条消息，不再被旧请求锁死。
- WebUI Hook 在终态后停止计时；原有正常流式、工具和 FC 任务测试不回归。
- 重启本地服务后，用自然语言分别完成代码提案链路和动态插件链路；只有两者都正常结束，
  才输出视频录制流程。
