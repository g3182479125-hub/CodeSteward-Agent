# 计划评估与取舍

依据：本机冻结计划 2.0.0（第 1–9、11 节）、ADR-0002/0003、P5 acceptance，
以及本次读取的 nanobot 工具、DevPilot 执行和确认代码。现有 ADR 引用 2.2.0，
但当前未获得该原文；本评估不宣称核验了它。未重新执行产品或云端测试。

| 问题 | 可定位依据 | 处理 |
|---|---|---|
| 技术清单代替用户完成任务 | 冻结计划 §6.4 九类页面，§8 P5 页面节点；ADR-0003 已取消 | 一个聊天流程；不恢复独立控制台 |
| 已有能力与新增价值不清 | nanobot `agent/tools/filesystem.py`、`shell.py`；DevPilot 计划 §1 | 复用聊天/模型/通用工具，DevPilot 只承担受控交付增量 |
| 受控模式是否存在旁路缺验收 | nanobot file 默认启用；DevPilot 的 Broker 校验仅覆盖自身入口 | P6-01 验证实际工具集合；这是需查证的部署风险，不把源码默认值当运行事实 |
| 接口理想图与源码落差 | 计划 §5.1 六方法；`execution.py` 当前 Protocol 只有 run | 复用端口并补所需生命周期行为，不重建框架 |
| 清理/失败细节被大词掩盖 | `fc_sandbox.py` kill 异常被忽略，退出码缺失默认 0 | P6-02 明确清理结果、未知状态和错误映射；待开发，未声称已修复 |
| 验证种类不等于回归能力 | `verification.py` 语法/运行等 profile | 先锁定一个真正回归检查和预置依赖，再做真实闭环 |
| “执行”含义与用户预期冲突 | 用户希望 Apply 后验证；当前 ConfirmedActionTool 分动作 | 定义组合操作授权，不偷偷复用单动作令牌 |
| 自动化通过与产品可用混淆 | P5 acceptance 明示 provider-backed live chat 未验证 | P5 历史不重做；真实聊天+FC 列为 P6 明确验收 |
| 计划入口分散/版本缺失 | 仓库外计划 2.0.0，ADR 引用 2.2.0，README 指旧交接 | 仓库内单一 CURRENT_PLAN + 明确优先级 |
| 审查和文档自我循环 | 多轮候选、重复 final/manifest；ADR-0004 已定义改进 | 沿用双审，按增量和风险复审，最小证据集合 |

## 为什么保留 DevPilot

直接用 nanobot 通用工具更简单，但会放弃已经构建的补丁前置校验、一次确认、
可追踪验证与冲突保护。推倒重来成本更高。本次选择复用现有 DevPilot，收紧
未来扩展；不把每项内部机制当作独立产品，也不为展示架构添加模块。

## 不应删掉的内容

路径/凭据约束、确认与不可变补丁、重复执行保护、回滚冲突、执行预算、取消清理、
真实测试和故障恢复，直接关系到用户文件和云端运行，保留。纳米机器人现有能力
能否复用，以部署配置和测试为准，不因名字相似就断言等价。

## 新旧路线对应

P0–P5：沿用历史成果；P6-01：补真实入口和当前契约；P6-02：补 FC 生命周期；
P6-03：实际隔离/功能验收；P6-04：复核启用；P7-01/02/03：保留编号，合并批次。
旧 Golden/安全用例继续保留；不再扩大前端、Skill 市场和可选工作流范围。
