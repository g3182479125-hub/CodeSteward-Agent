# ADR-0007：受控 Skill 改进，复用 nanobot 而非重复建设

状态：2026-09-06 用户明确批准上一轮方案并要求最终计划，采纳。

CURRENT_PLAN 3.3 继承 ADR-0006 的 nanobot 单 Runtime 路线，在 P7 补上下文定位、
无效循环检测和真实任务评测；P7 基础交付后增加 P8 单 Skill 改进试点，再接定时
批处理作为可选扩展。P8-01/02 可独立完成并交付，未选择 P8-03 不阻塞主版本；
选择后才执行其验收。仅此范围覆盖旧计划的新增工作流排除；P0–P5、P6 门禁、ADR-0004 不变。

源码事实：当前 nanobot 已有 Cron；Dream 提示词及 build_dream_tools 已支持
工作区 Skill 创建/合并。不能将这些作为本项目新原创。增量是证据归因、候选隔离、
固定评测、用户确认启用及恢复，不训练模型权重，不引入第二调度器/记忆库。

选择：不采用“只让 Dream 直接写 Skill”，也不采用全自动生效。单 Skill 的受控
闭环满足个人项目的可维护性与可验证性。必须限制现有 Dream 直写等实际可达入口，
不能只在新界面审批而保留绕过路径。不得靠提示词执行权限限制。

确认边界：项目补丁继续复用 DevPilot `ActionBroker`；Skill 激活不是 ChangeSet
动作，不能伪装成 Apply/Verify/Rollback，因此只在同一私有持久化与原生 nanobot
聊天入口中使用最小 `ConfirmationRecord`。它绑定用户、会话、工作区、项目、Skill
及基础/候选哈希、固定测试集和过期时间，仅能消费一次以激活对应候选，不产生项目
变更能力，也不允许模型提供确认凭据。

本次交付为计划文档；不创建实际定时任务、不启用云服务、不修改运行配置。
详细规格为 CURRENT_PLAN 与 SKILL_IMPROVEMENT，后续模型按节点读取并验收。
