# ADR-0005：以精简执行计划接管后续开发

状态：按用户本次“优化计划、简要不冗余、保留必要功能与设计”请求采纳。

当前需求及剩余路线统一由 [CURRENT_PLAN.md](../plans/CURRENT_PLAN.md) 3.0 提供。
原冻结计划和 P0–P5 证据保留为历史来源；不原地改写仓库外文件。
CURRENT_PLAN 不依赖缺失的冻结计划 2.2.0，即可定义后续任务。

优先顺序：用户后续明确决定 → CURRENT_PLAN（产品/路线）与 ADR-0004（审查流程）
→ ADR-0002/0003 未被新计划明确修改的安全契约 → 历史计划及交接。
新计划第 2 节将 Apply+Verify 定义为待实现的显式组合授权，替代“只能分别点击”
的交互约束；分别鉴权、不可重放、token 保密、撤销单独确认仍然保留。

受控修订范围：取消旧独立控制台要求；后续不扩建 Skill 发布平台/可选重构线；
P6 复用已有 FC run 适配器，按真实需求补生命周期能力；P7 合并交付批次。
保留旧安全用例、现有功能兼容性、人工复核、无合格后端拒绝及原补丁/修复预算。
旧接口的精确方法列表和目录布局不再要求照搬，但对应安全行为必须满足。

背景与依据见 [计划评估](../plans/PLAN_ASSESSMENT.md)。本轮只修改计划文档，
不启用执行能力、不实现组合授权、不删除已有功能。
