## 结论

当前分支已经覆盖了一个关键兼容场景：旧 H8 checkpoint 的
`remaining_iterations=0` 不会阻止同一会话收到新的普通用户消息。这个场景的
回归测试 `test_exhausted_h8_budget_does_not_pause_next_plain_chat_turn` 当前通过，
并且模型在新消息上确实被调用。

因此，R0 没有把这个入口重复改一遍。剩余问题不是简单的“预算值为 0 永久锁死”，
而是失败事实仍然分散在内部 stop reason、异常文本、delivery 和 WebSocket 投影中：

- 用户可能仍看到内部暂停/异常语句，而不是当前轮停止和下一步；
- 失败没有稳定的 outcome 分类，刷新或重连时不能用同一事实解释；
- 任务 profile 等 BUILD 阶段失败还会走另一条 delivery 兜底路径；
- WebUI 现有活动轨迹尚未收到版本化的 turn outcome 事件。
