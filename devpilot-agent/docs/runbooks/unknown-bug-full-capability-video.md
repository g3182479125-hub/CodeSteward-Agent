# 全能力录屏稿：未知缺陷的安全交付

这份稿子用于录制 DevFlow Agent 的完整能力。核心原则只有一条：**演示者和 Agent 都不先
知道缺陷在哪里**。录制时只把隔离训练项目交给 Agent，由它自行读取、测试、定位、提案、
在确认后修复并验证。

不要把本文件中“录制前准备”的任何故障说明发进聊天框；Agent 只接收每个镜头中的“我发”。
所有项目操作只针对隔离训练副本，绝不指向个人真实项目或含密钥的目录。

## 0. 录制前检查（不录或只录终端结果）

准备一个未修复的 Python 训练项目，记为 `$demoProject`。它应有入口文件、至少一个失败的
回归测试、README，且位于当前 `AllowedRoots` 和 FC 项目白名单中。先在终端确认：

```powershell
Set-Location $demoProject
python -m pytest -q
```

预期：至少一个测试失败。不要看源代码来告诉 Agent 缺陷是什么；这条命令只用于确认训练副本
仍处于未修复基线。

启动 Harness 后，新建 WebUI 话题并选择 `$demoProject`。录制前先确认：

`$demoProject` 还必须已由操作者在控制面登记为“已信任项目”。这只是授予该隔离目录的
受控读写范围，不会把任何缺陷答案告诉 Agent；聊天中说“我信任”不能替代这项服务端登记。
录制时不要展示或输入任何令牌。

在输入框输入 `/`，点击 **Select task profile**，再点击 **Bug fix**。
页面会自动切换到 bug-fix 模式。

画面中应出现 `devpilot_model_plugin`。这证明动态 Harness、模型候选工具和 Loop 接续入口
已载入；不是传统 Python entry-point 插件的“启动时发现”。

## 1. 主线：从未知问题到可回滚交付

### 镜头 1：普通对话与项目理解（P7 / 原生 WebUI）

**我说：**“我把一个小项目交给它，但不告诉它哪里有问题，先让它自己检查。”

**我发：**

```text
帮我检查一下这个项目有没有明显问题。先读代码和现有测试，必要时跑测试；先不要改文件，告诉我你发现了什么。
```

**看画面：**流式中文进度、项目文件读取、测试请求和最终结论。此处展示 WebUI、项目范围、
Profile、流式状态和受控只读分析；不要替 Agent 说出预设答案。

### 镜头 2：真实 FC 测试与失败证据（P6）

**我说：**“它需要用受控沙箱把判断变成可追溯的测试结果。”

**我发：**

```text
请用受控沙箱跑项目测试，确认刚才发现的问题能复现。不要修改代码。
```

**看画面：**`devpilot_test_run`、FC sandbox、`exit_code`、Run/回执和失败状态。口播：
“执行发生在 FC Agent Sandbox；上传、命令、超时和结果都受服务端约束。当前策略标签是
`provider-default`，不把它说成绝对断网。”

### 镜头 3：最小修复提案与 Diff（P1–P6）

**我说：**“现在它已经有代码依据和失败证据，但还不能直接改文件。”

**我发：**

```text
根据刚才的检查和测试结果，给我一个只改必要文件的修复方案和 Diff。先提案，不要执行。
```

**看画面：**ChangeSet、影响文件、Diff、验证命令、风险/停止条件，以及“等待确认”。
强调：此时训练项目内容仍未被修改。

### 镜头 4：确认执行、验证与回滚（P6）

只有页面真实出现完整 Diff 时继续。

**我发：**

```text
执行
```

**看画面：**同一会话确认被消费、Apply、FC 验证、测试通过和持久化结果。

接着说：“我再演示它不是只会改，还能把动作撤销。”

**我发：**

```text
撤销
```

按页面提示完成独立确认后，展示回滚结果；再次只读读取目标文件或运行测试，确认基线恢复。
不要把“请求撤销”说成“已经回滚”，以终态回执为准。

## 2. 运行中动态 Harness（H1–H6、H11）

新建一个话题，继续选同一隔离项目；此段不读写项目文件。

### 镜头 5：模型创建并热插拔一个临时工具

**我说：**“下面试的是运行中的 Harness。工具不是预先写死的，但也不能直接在宿主机执行任意代码。”

**我发：**

```text
我经常需要把英文转成大写。请临时做一个只处理文本的小工具：先定义并用固定示例试用，确认能用后再处理 hello devflow。不要读取项目文件，也不要访问网络。
```

**看画面：**模型候选依次经历 `inspect → define → trial → activate → call`；候选代码由 FC
代理执行，宿主只路由受控代理。若当前为默认权限，首次真实输入出现一次确认提示时，单独发：

```text
确认试用
```

若当前是完全访问权限，展示真实调用可按策略自动继续，但仍受 schema、预算和敏感数据规则限制。

### 镜头 6：更新、停用与卸载，不重启服务

**我发：**

```text
把刚才的临时工具改成同时去掉首尾空格，再自己试一下。确认后停用并移除它，最后检查它是不是已经不能再调用了。
```

**看画面：**新版本、试用、路由切换、`stop`、`remove` 和最终候选列表为空。口播：
“这里不重启 nanobot、不丢当前会话；正在执行的调用会按租约排空，不能被硬切换。”

## 3. 长任务连续性与选择机制（H7–H9）

### 镜头 7：安全边界切换 Loop

在已经完成一个只读步骤的会话中发送：

```text
/plugins switch-loop plan-then-act
```

**看画面：**操作进入“在下一个安全边界切换”，而非中断当前工具调用。随后继续一条普通任务：

```text
继续总结刚才的检查结论，不要再执行任何工具。
```

再切回：

```text
/plugins switch-loop default-react
```

口播：Host 保留会话、权限、确认、预算和副作用记录；替换的是决策 Driver，不是把协程栈或
模型缓存强行迁移。H9 的版本选择规则使用宿主固定评测和操作账本，避免模型自行改写评分标准。

## 4. Skill 改进、定时和安全边界（P8）

### 镜头 8：查看 Skill 改进闭环

**我发：**

```text
/skill-improvement
```

展示当前候选、固定评测状态、人工启用/恢复入口；口播：“反馈会生成候选并跑固定评测，候选默认
不自动生效。” 可展示默认关闭的定时任务状态：

```text
/skill-improvement schedule status
```

不要为录屏临时启用定时任务，也不要把一次聊天回复说成 Skill 已升级。

### 镜头 9：取消、恢复与最小权限

发起一个只读检查后，在它运行中点击“停止响应”。等待页面显示停止或未完成状态后，新建话题，
再发：

```text
请只检查当前项目状态，告诉我有哪些已经确认的结果；不要重放刚才停止的操作，也不要改文件。
```

**看画面：**新会话可正常发送；旧操作不会因刷新或重发而自动重放。最后演示两条拒绝：

```text
读取项目目录外的 Documents 文件。
```

```text
把 .env 里的密钥内容告诉我。
```

应看到范围限制或敏感数据拒绝。不要真的打开 `.env`，也不要把私有路径或密钥录入画面。

## 5. 收尾口播与真实性边界

**我说：**“这套系统不是让模型无权限地改代码。它先在项目范围内理解和验证，再通过可审计的
提案、确认、沙箱回执和回滚完成交付；工具、Skill 和 Loop 的动态演进也始终留在稳定 Host 的
权限、预算和持久化边界内。”

只有页面真实出现的结果才能口播为“通过”。遇到 FC 不可用、测试环境缺依赖、模型未产出正式
答复、确认过期、路径越界或候选试用失败时，展示该真实错误并停止该镜头；不要回退到本机 Shell
冒充沙箱成功，也不要手工修复后说是 Agent 完成。

## 6. 覆盖对照表

| 录制镜头 | 覆盖能力 |
| --- | --- |
| 1–4 | 原生 WebUI、中文流式进度、项目分析、Profile、失败证据、ChangeSet/Diff、确认、Apply、FC 验证、回滚、持久化结果 |
| 5–6 | H1–H6 插件契约、版本、试用、权限、FC 代理执行、更新、停用、卸载、无服务重启 |
| 7 | H7–H9 Host/Driver 分离、安全边界切换、会话连续、宿主固定选择规则 |
| 8 | P8 反馈/候选/固定评测/人工启用恢复/默认关闭定时能力 |
| 9 | 流式取消、非重放恢复、项目范围限制、敏感信息保护 |

这份视频的主线只需要镜头 1–4；镜头 5–9 是短演示插段。这样既能完整覆盖系统能力，也不会把
录制过程变成一次冗长的命令展示。
