## 已做的关键修复

- 配置存在但没有真实验证的 execution backend 显示为 `unavailable`，不再把“已配置”当成可执行。
- `/api/v1` 和 `/v1` 使用同一套安全公开响应清理逻辑，去除 `project_path`/`real_path` 并脱敏字符串。
- Diff 中的 `sk-`、`e2b_`、GitHub/AWS token、Bearer，以及 `api_key`/`token` 等赋值内容会脱敏，覆盖引号和 triple-quote 场景。
- DevPilot API 只允许 loopback，供 nanobot Adapter/Broker 调用，不作为用户页面 API。
- SSE 保留为内部事件源；nanobot 适配层负责脱敏、阶段映射和持久快照降级。
- capability token 不进入模型消息、Tool 结果、Session、WebUI 文本、SSE、日志或 Artifact。
- rollback 的交付元数据改用 canonical `/api/v1` endpoint。
- 原 browser smoke 属于已删除控制台的历史证据，不再作为当前门禁；当前门禁改为 nanobot
  Tool/事件桥接、Broker 边界和 Fake backend 聊天集成证据。

## 明天在另一台电脑上的恢复步骤

```powershell
git clone https://github.com/g3182479125-hub/devflow-agent.git
cd devflow-agent\devpilot-agent
uv sync --dev
```

如果已经 clone 过：

```powershell
git pull origin main
git status
```

推荐把测试临时目录放在 E 盘（本机 C 盘 Temp 曾出现权限问题）：

```powershell
New-Item -ItemType Directory -Force E:\codex-local\pytest-temp | Out-Null
$env:TEMP = "E:\codex-local\pytest-temp"
$env:TMP = "E:\codex-local\pytest-temp"
uv run pytest
uv run ruff check src tests
uv run pyright
```

本地启动：

```powershell
$env:DEVPILOT_ENABLE_EXPERIMENTAL_CONTROL_PLANE = "1"
$env:DEVPILOT_ALLOWED_ROOTS = "E:\codex-local"
$env:DEVPILOT_DATA_DIR = "E:\codex-local\nanobot-state\devpilot-data"
uv run devpilot serve --host 127.0.0.1 --port 18800
```

API health：`http://127.0.0.1:18800/healthz`

用户界面：nanobot 自带 WebUI；不要启动 18801 或任何 DevPilot 独立页面。

## P6 开始前必须确认的事项

P6 的核心不是再做一个普通页面，而是把真实 FC Agent Sandbox execution port 做成
可验证、可审计、fail-closed 的执行后端。开始前应先阅读：

- `docs/adr/ADR-0002-fc-agent-sandbox-execution-port.md`
- `docs/adr/ADR-0001-code-delivery-pivot-and-sandbox-port.md`
- `docs/evidence/phase-3/fc-sandbox-port-acceptance.md`
- `docs/reviews/fc-sandbox-port-product-review-plan.md`

此前本机曾出现 `devpilot sandbox-check` 返回 `FC_EXECUTION_FAILED` 的情况，
因此不能只检查环境变量或 API Key 是否存在；必须验证真实地域 endpoint、template、
请求协议、返回值、超时/错误映射、文件包边界和销毁行为。FC 真实连通性未通过前，
P4/P5 的 Fake backend 保护不能解除，也不能把“配置成功”显示成“Sandbox 可用”。
