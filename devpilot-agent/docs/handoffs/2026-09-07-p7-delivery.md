## 换机安装

在新目录执行：

```powershell
cd D:\path\to\nanobot-devpilot-agent
uv sync --project .\nanobot --locked
uv pip install --python .\nanobot\.venv\Scripts\python.exe -e .\devpilot-agent
```

确认 nanobot 的运行环境同时发现 nanobot 和 DevPilot：

```powershell
.\nanobot\.venv\Scripts\python.exe -c "import importlib.metadata as m; print(m.version('nanobot-ai')); print(m.version('devpilot-agent')); print(sorted(ep.name for ep in m.entry_points(group='nanobot.tools') if ep.name.startswith('devpilot_')))"
```

预期：nanobot `0.3.0`、DevPilot `0.1.0`，14 个 `devpilot_*` entry points。控制面可以
使用单独的 `devpilot-agent/.venv`，但 nanobot 进程不能改用未安装 DevPilot 的环境。

## 配置与启动

1. 将 `devpilot-agent/.env.example` 复制为本机未跟踪的 `.env`，填写数据目录、受信项目根目录和 loopback 端口。
2. 在 nanobot 本地配置填写 DeepSeek/OpenAI-compatible 模型、Base URL、模型名和 API key。
3. FC 仅在需要真实验证时配置本机环境变量 `E2B_API_KEY`、`E2B_API_URL`、`E2B_DOMAIN`、
   `DEVPILOT_FC_TEMPLATE`；key 不写入文件、Prompt、Session、日志或 Git。
4. 在 `devpilot-agent` 目录执行迁移并启动控制面：

```powershell
$env:DEVPILOT_ENABLE_EXPERIMENTAL_CONTROL_PLANE = "1"
$env:DEVPILOT_ENABLE_FC_SANDBOX = "0"
$env:DEVPILOT_ALLOWED_ROOTS = "D:\path\to\allowed-projects"
$env:DEVPILOT_DATA_DIR = "D:\path\to\devpilot-agent\local-data"
uv run --no-sync alembic upgrade head
uv run --no-sync devpilot serve --host 127.0.0.1 --port 18800
```

5. 用同一个 `nanobot/.venv` 启动 nanobot Gateway/WebUI，用户只在 nanobot 聊天中发起
   分析、提案和“执行/验证/撤销”确认。不要启动 `web/`、Vite 或 18801 独立页面。

## 恢复与排障

- 迁移前复制 `local-data/devpilot.db` 到备份目录；恢复时复制到新的隔离 `local-data`，
  先执行 `alembic upgrade head`，确认 `alembic_version`，再启动服务；不覆盖旧目录。
- `nanobot.tools` 为空：确认命令使用 `nanobot/.venv`，并重新执行 DevPilot editable install。
- `API offline`：检查控制面 18800 和环境变量；端口占用时换端口并同步 loopback URL。
- `PROJECT_TRUST_REQUIRED`：先在 nanobot 聊天中完成项目来源和路径确认。
- `APPROVAL_BROKER_UNAVAILABLE`：确认提案与当前 chat、ChangeSet tuple 和当前请求上下文一致；
  不把 token 粘贴给模型，不绕过 fail closed。
- FC 报错：P6 当前杭州 `provider-default` 只证明供应商默认网络策略下可执行，不能宣称网络隔离；
  strict 断网能力仍未验收。不要把 API key/region 配置成功当作 Sandbox 完成。
