## Objective and limits

Provide real local evidence for Skill hot refresh, temporary Tool validation/attach/call/update/stop, a built-in Loop Driver checkpoint handoff, and the ShopSphere local ChangeSet delivery chain. Keep FC disabled and prove zero FC backend construction/contact. Do not include Skill self-evolution or FC/cloud behavior, and do not alter completed P0–P8/H1–H11 historical evidence.

The local temporary-tool flow executes candidate Python as the current Windows user, with host-default network. It is **not** an OS sandbox or privacy isolation. Use disposable folders and synthetic content only. No model-provided command, interpreter, environment, dependency, or execution profile is accepted.

## Implementation slices (TDD)

1. **Fixed local contract profile.** Add public-seam tests proving `LocalExecutionBackend` accepts exactly the server-selected temporary contract command, materializes only the provided immutable bundle, executes the shipped checker, returns `backend=local`, `execution_location=local`, blank sandbox ID and host-default network label, and removes its work directory. Reject command/profile mismatch and arbitrary commands before materialization. Implement only after the red tests.
2. **Hash- and scope-bound validation receipt.** Test local validator success/failure, output bounds/redaction, and durable receipt fields for tool/version/source hash/session/Run/project/checker version/execution ID/backend/location/exit status. A missing, stale, failed, mismatched-scope, or mismatched-hash receipt must not activate. Temporary-tool registration accepts only fully bound local receipts and rejects legacy FC receipts; do not claim a local receipt is an FC attestation.
3. **Temporary Tool lifecycle chooses local only.** Replace direct FC construction in validate, activate revalidation, ensure-chain, and persist revalidation with one local backend factory owned by this feature. Add spies proving zero FC builder calls across positive, negative, update, stop/remove, cleanup, and persistence paths. Preserve existing Full Access/WebSocket scope, privacy/external-side-effect confirmation, PluginManager lease, versioning and cleanup rules.
4. **Live runtime seams.** Add focused tests for same `ContextBuilder` observing changed Skill text, an activated Tool appearing only in its session's next-step schema and executing via the normal PluginManager view, version switching/lease draining/stop and Run-end cleanup, and built-in Driver switch only at a committed checkpoint. Do not assert that AgentLoop implementation code is hot-swapped.
5. **ShopSphere rehearsal and evidence.** Work only on the challenge copy. Verify defect baseline, use the personal Agent UI to generate the real ChangeSet, review Diff, keep explicit Apply confirmation, run local Apply+Verify and full test suite; exercise Rollback only on an extra disposable clone. Capture hashes, Run/ChangeSet IDs, process/session IDs, test output and zero-FC proof. No manual source patch is allowed in the challenge.
6. **Recording package and verification.** Update the user-facing recording checklist to call out the local/non-sandbox trust boundary and exclude Skill evolution/FC. Run focused temporary-tool and local-execution tests, affected PluginManager/Agent tests, DevPilot regression tests, Ruff/type checks supported by the repo, and `git diff --check`. Record actual commands and exits.
7. **Fixed candidate review.** Freeze one implementation candidate SHA and diff. Dispatch independent Standards and Spec subagents in parallel using this spec, CURRENT_PLAN §§0/6/7 and ADR-0004. Batch valid findings, fix and rerun affected checks, then have the same reviewers inspect the increment. Record both reports and do not claim complete pending live WebUI evidence or either review PASS.

## Acceptance checklist

- [ ] With FC disabled, create/validate/activate/call/update/stop/remove works through the real WebUI in one running Agent process; one other session does not see the temporary Tool.
- [ ] Skill file changes appear in the next model context without restarting Gateway, Loop or session.
- [ ] Built-in `default-react` ↔ `plan-then-act` transition uses a committed checkpoint in the same Host/process/task and does not replay effects.
- [ ] All local receipts are explicitly local, bounded, durable, and bound to immutable candidate and session/Run/project identity. Stale, structurally invalid, or mismatched receipts fail closed.
- [ ] FC spy evidence: zero FC construction, prepare, run, cleanup, or fallback calls during the local flow.
- [ ] ShopSphere defect is repaired only by the Agent's real ChangeSet path; Apply confirmation remains; local tests pass; rollback/hash is shown on a disposable copy only.
- [ ] Recording materials explicitly state: “本机执行（非 OS 沙箱；候选代码继承当前用户权限）”. Skill self-evolution and every FC/cloud function are explicitly excluded.
- [ ] A separate Standards review and Spec review both PASS on the final implementation candidate; all valid findings are closed and affected checks pass.
