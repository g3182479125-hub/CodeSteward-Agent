# 完全访问直通执行设计

## 目标

当用户在 WebUI 选择“完全访问权限”时，DevPilot 应直接完成常规开发工作，不再要求先失败的测试证据、项目信任、范围哈希、ChangeSet 批准令牌或 Apply/Verify 二次确认。

## 范围

直通模式覆盖项目内读写文件、执行命令、测试、依赖安装、代码修改、Skill/工具/Loop 的热插拔和验证。它保留 ChangeSet、Diff、执行回执和回滚记录作为可见审计信息，但这些信息不再构成执行前置条件。

受控模式保持现状：未选择完全访问时，现有证据、批准与信任机制继续生效。

## 隐私确认边界

直通模式只在下列动作前要求一次用户确认：读取、发送、上传或在回复中展示可能含密钥、凭据、个人文件、聊天记录、浏览器数据或其他隐私内容的数据。

项目源代码、常规构建输出、测试日志与用户已明确提供的项目路径不属于该二次确认范围。检测到疑似敏感数据时，默认不在聊天中回显其原始值。

## 架构

1. WebUI 将“完全访问权限”作为受信的执行策略传入运行时请求上下文。
2. DevPilot 工具适配器根据该策略选择受控流程或直通流程。
3. 直通流程仍调用同一项目边界、执行后端和补丁引擎，但跳过证据、项目 trust、令牌和二次批准门槛。
4. 隐私分类在真正读取或外发敏感内容的边界执行，返回一次清晰的确认请求；确认后只对该动作继续。
5. 409 响应保留稳定错误码和可操作说明，避免把流程冲突误报为沙箱失败。

## 验证

- 完全访问下，小型代码修改可以从自然语言请求直接到写入和测试，无 409 工作流阻断。
- 完全访问下，敏感路径或疑似秘密内容会要求一次确认，且不会泄露原文。
- 未开启完全访问时，现有受控流程回归测试保持通过。
- WebUI 清楚展示实际策略与隐私确认原因。
